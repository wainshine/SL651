## 三、新发现缺陷（Low）

### L-1 「静默截断」缺陷类未外推：B0/C0 非数组 func 多记录与查询响应尾随字节仍无 warning 丢弃

**位置**：
- `sl427/decoder.py:1309-1330`（B0 分支：非数组 func `real_data` → `_parse_ctrl_func_data(func_code, real_data)`，该函数对非数组类型解析完首条即 `break`）
- `sl427/decoder.py:1267-1306`（C0 分支：正常与降级两条子路径同款）
- `sl427/decoder.py:508/568/575/586/596/628/638/724`（`_parse_query_response` 内 8 处 `len(body) // record_len` 整除截断，余数静默丢弃）

**问题**：v2.8 L-1 确立了「降级必须留痕」原则并为 B1 补了 consumed 对账 + warning，但**同一缺陷类存在于其他分支**：
1. **B0 非数组 func**：实测 B0/func=0x01（雨量，3B）带 2 条记录（real_data 6B）→ 仅输出第 1 条「雨量 100.0」，第 2 条 3B 无 warning 消失；对照数组 func=0x02（水位）2 条记录正常全展开——证明截断仅限非数组 func；
2. **C0**：同款调用（自报实时数据），非数组 func 多记录同样静默截断；
3. **查询响应**：实测 AFN=64 body 7B → 输出 1 条「流量上限[1]」，尾随 2B 无 warning 丢弃；`_parse_query_response` 其余 7 处 `//` 截断点同款模式。

**影响评估**：这些分支的多记录/尾随字节属非标或畸形输入（B0 查询响应规约语义为单值 + alarm + state；数组 func 本就全展开），**首条记录值仍正确、不崩溃、不错值**，故定级 Low。但违背本项目 v2.8 L-1 确立的「降级必须留痕」原则：无法回答「丢的 3B 是数据还是乱码」。

**为什么前轮没发现**：v2.8 L-1 的修复范围按报告字面锁定 B1 分支（固态存储多记录是常态场景，影响最大）；修复后无「同类分支横向扫描」步骤，且测试只补了 B1 的断言——没有一个通用契约测试断言「任何分支不得无痕丢字节」，导致同类问题在其他分支继续潜伏。

**修复建议**（沿用 v2.8 对抗复核已确立的前置条件）：
1. **先解决 consumed 信息**：按 v2.8 复核意见把 `_parse_ctrl_func_data` 改为返回 `(elements, consumed)`（或新增薄包装在返回后按 `len(data) - consumed` 计算余量）；B0/C0 的非数组 func 路径在余量非零时 append warning（措辞与 B1 一致：「已解析 XB，剩余 YB 未展开」）；
2. **查询响应 8 处整除截断**：每处补 `if len(body) % record_len: warnings.append(...)`；不必逐处手写，可提取 `_expand_records(body, record_len, warnings)` 小工具单点实现——遵循本项目「同源判定单点实现」规律；
3. **补通用反静默丢弃契约测试**：对 B0（非数组 func）/C0/查询响应各构造「多一条记录」payload，断言 warning 存在；该测试应在修复前先写（红→绿），防止下一轮再修 B1 忘 B0；
4. **优先级**：本项无数据正确性风险，可与下轮其他 Low 合并修复；不建议为此单独发版。

## 十、复现附注

（Python 3.10+，`sl651-toolkit` 加入 `sys.path`）

- **M-1 验收**：`SL651Encoder(center_addr=1, station_addr="1234567890", password=0x1234, station_type=0x4B).build_ascii_frame([("pH","7.2")])` → 解码得 `code='pH', name='pH'`；`_lookup_ascii("PH")/("ph")` 均命中 `("pH","")`。
- **M-2 验收**：v2.8 原样本 payload（`dc17f0…2382`，39B）按 DIVS=3/2/1 三分片 `feed()` → `warnings` 含「数据域解析失败，降级为原始摘要: 无效 BCD 字节: 0x7D」，消息产出、无异常；同 payload 单帧 `decode()` → `DecodeError: 数据域解析失败: 无效 BCD 字节: 0x7D`。
- **L-1(v2.8) 验收**：`hdr=010108240102011530`（注意：头内起止时间按 `[时,日,月,年]` 4B 布局构造，否则会叠加 L-2 告警）+ `001000`×12 → 12 条雨量；尾随 `\x01` → 「剩余 1B 未展开」。
- **L-2(v2.8) 验收**：起止时间 `30240102` → `-` + warning；`0A300225`（2月30日）→ `-` + warning（真实日历）；`08011125` → `2025-11-01 08:00` 无误报。
- **新 L-1 验收**：B0/func=0x01，D = `001000 002000 00000000`（2 条雨量 + alarm/state）→ 仅 1 条「雨量 100.0」无 warning；对照 func=0x02 两条水位全展开。AFN=64 body 7B → 1 条 + 尾随 2B 静默。
- **强变异**：A 组 = 9 func × 200 组「payload 随机字节（含 0xAA/0xFF/0x7D/0x9C）→ 随机 1~4 分片 → 逐片 `build_frame(divs=…, CRC 有效)` → `feed()`」，0 未受控异常；C 组 = SL651 定时报帧随机破坏 1~3 字节 + 随机单点切碎 `feed()`，3000 帧 0 未受控异常。
