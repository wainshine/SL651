## 二、严重缺陷（Critical）

### ✅ [C-1] `sl427/encoder.py:240` — `build_set_recharge()` 充值量编码偏差

**源码**:
```python
def build_set_recharge(self, amount: float, pw: int = 0) -> bytes:
    v = int(round(amount * 1000))
    data = int_to_bcd_bytes(v, 4)
    return self.build_param_set_frame(0x15, 0x00, data, pw)
```

**问题**：规约 SL427-2021 §7.2.5 规定充值量为 4 字节压缩 BCD，取值范围 `0~99999999`，单位为 `m³`，**不含小数**。代码将 `amount * 1000` 后编码，导致存储值放大 1000 倍。例如传入 `1234.0`，存储值为 `1,234,000`，接收方解码后得到 `1,234,000 m³` 而非预期的 `1,234 m³`。

**验证**：
```
>>> build_set_recharge(1234.0)
# 数据域 BCD 存储值为 01234000 = 1,234,000（预期 1234）
```

**影响**：与真实 RTU 设备互通时，充值量数据将完全错误，属于数据完整性缺陷。

**修复（v1.2.0）**：已移除 ×1000，amount 按 m³ 整数编码（规约 §7.2.5）。

## 三、中等缺陷（Medium）

### ✅ [M-1] `sl427/encoder.py:238` — `build_set_work_mode()` docstring 映射错误

**源码 docstring**:
```python
"""设置工作模式 (AFN=12H)。mode: 0=自报, 1=查询/应答, 2=兼容, 3=调试。"""
```

**规约定义**（SL427-2021 §7.2.4）:

| 值 | 规约含义 |
|----|----------|
| 00H | 兼容工作模式 |
| 01H | 自报工作模式 |
| 02H | 查询/应答工作模式 |
| 03H | 调试/维修模式 |

Docstring 将 mode 含义全部写错：`0=自报` 应为 `0=兼容`，`1=查询/应答` 应为 `1=自报`，`2=兼容` 应为 `2=查询/应答`。

**修复（v1.2.0）**：docstring 已修正为 0=兼容, 1=自报, 2=查询/应答, 3=调试（规约 §7.2.4）。

### ✅ [M-2] `sl651/encoder.py:56` — 串号范围不符合规约

**源码**:
```python
self._serial = int(datetime.now().timestamp()) % 65535
# ...
def _next_serial(self) -> int:
    self._serial = (self._serial + 1) % 65535
    return self._serial
```

**问题**：SL651-2014 规定流水号范围 `1~65535`。`% 65535` 导致取值范围为 `0~65534`：
- 串号 `0` 不在规约允许范围内
- 串号 `65535` 永远无法产生（`(65534 + 1) % 65535 = 0`）

**修复（v1.2.0）**：初始值 `% 65535 + 1`，循环 `(val + 1) % 65535 or 1`，范围 1~65535。

Web 解码界面 `web/app.py` 需要 `flask`，但未在 `requirements.txt` 中声明。部署 Web 服务时会因为缺少依赖而报错。

### ✅ [M-4] `sl427/decoder.py:211` — `_format_addr()` 方式2 格式化缺零填充

**源码**:
```python
for b in addr[1:]:
    hex_code += f"{b:X}"      # 缺零填充
```

**问题**：方式2 地址按 nibble-packed 编码（每个字节存两个 HEX 数字）。当某个字节值 < 16 时，`f"{b:X}"` 只输出 1 位十六进制字符，导致最终字符串长度不是 8 位。例如字节值 `0x0A` 输出 `"A"` 而非 `"0A"`。

**修复（v1.2.0）**：已改为 `f"{b:02X}"` 零填充。

### [L-4] `sl427/constants.py:102` — `COMP_BITS` 映射不完全对应规约

```python
COMP_BITS = [0x0A, 0x0B, 0x06, 0x08, 0x05, 0x03, 0x02, 0x01]
```

规约表 45 定义的综合参数字段顺序为：雨量(D7)/水位(D6)/流量(D5)/闸位(D4)/气象(D3)/功率(D2)/土壤含水率(D1)/水质(D0)。当前代码将 气象(D3) 映射为 `0x08`（风速），但规约中 气象 包含 气压(0x07) + 风速(0x08) 两个要素。当前实现不完整但不会导致解析失败。
