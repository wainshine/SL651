## 二、发现并修复

### SA-1（Low，已修复）SL427 CLI 地址域未脱敏

**现象**：SL651 的中心/遥测站已遮，但 `format_sl427` 与 JSON `addr` 仍输出完整 `方式1 行政区划:110108 站址:1284`；`--show-raw` 之外也可见。

**复现**：
```bash
python3 tools/decode_cli.py sl427 --hex 68086880110108040502F2FA16
# 地址 : 方式1 行政区划:110108 站址:1284 (遥测站)
```

**修复**：新增 `_mask_addr()`，保留“方式1/方式2”标签，遮行政区划/站址/编码；text 与 `_sanitize_dict` 共用。新增 `test_cli_masking` SL427 断言。

### SA-2（Low，已修复）A 补齐 warning 误报

**现象**：`allow_a_pad` 路径下，只要 raw 首半字节为 A 就写“按 A 补齐解析”warning；若 A 后含非十进制字符（如 `A1B2...`），实际解析结果是 `-`，warning 与结果矛盾。

**修复**：先 `_make_element`，仅当产出的要素值不是 `-` 时才写 A 补齐 warning。

### SA-3（Low，已修复）短帧降级 warning 文案不准确

**现象**：C0/81/82 数据域 4B（含 alarm/state、缺 Tp）时仍提示“缺少 alarm/state/Tp”。

**修复**：4B 及以上提示“缺少 Tp”，<4B 才提示“缺少 alarm/state/Tp”。

### SA-4（Low，已修复）多包缓存上限只在 `feed()` 结束时执行

**现象**：`_evict_pending()` 仅在 feed 循环结束后调用；一次 `feed()` 内灌入大量未完成组时，缓存可短暂超过 8MB/64 组上限，之后才回落（最终有界，但存在瞬时峰值）。

**修复**：SL651/SL427 的 `feed()` 每处理 64 帧调用一次 `_evict_pending()`，仍保留结束时兜底。

### SA-5（Low，已修复）SL651 重同步未识别 ACK/NAK/ESC 结束符

**现象**：`_find_valid_start()` 只接受 ETX/ETB/EOT/ENQ；下行确认帧以 ACK/NAK/ESC 结尾时，重同步可能跳过，最终靠缓冲上限逐字节恢复（正确性不受影响，仅变慢）。

**修复**：`sl651/constants.py` 增加 `ACK=0x06/NAK=0x15/ESC=0x1B`，重同步集合扩展为 7 种结束符。
